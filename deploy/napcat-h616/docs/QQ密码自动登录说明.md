# QQ密码回退登录

双击 [填写QQ自动登录账号密码.cmd](../填写QQ自动登录账号密码.cmd)，保持开发板USB连接。工具自动读取当前监听账号，只填写该QQ的账号密码，再点击“保存到开发板，保持当前QQ运行”。

这不是WebUI的Token，也不是飞书机器人密钥。密码不要发送到聊天里。

此前“未保存”报错已修复：旧版USB传输等待结束信号而超时，现改为一行JSON请求。请关闭旧配置窗口，从根目录入口重新打开。已用合成密码验证USB传输、临时存储及环境读取，生产密码文件未被测试覆盖。

保存位置是开发板 `/overlay/napcat-lab/private/qq-login.json`，目录权限700、文件权限600，仅root可读。该文件使用权限保护，并非加密存储。电脑上的工具只在内存中处理输入，不把密码保存到交付目录或电脑配置文件；传输使用USB标准输入，密码不放进命令参数或工具输出。

当前QQ继续在线。下次整个QQ进程启动时，受控入口读取凭据并通过环境变量交给NapCat：优先使用已保存的登录状态，失败后回退到密码登录。原来的QQ号、群名单、过滤关键词和飞书配置不改动。

保存成功只代表配置写入成功，不自动等同于QQ服务器已经验证密码。后续已经过受控重启实测：用户调整设备验证设置后，密码回退约52秒自动登录成功，核心就绪、双群补查及飞书验证通过，无需人工扫码。验证码、新设备验证或后续账号安全要求仍可能需要本人完成。

需要停用时，重新打开工具，点击“移除保存的密码（下次启动生效）”。已运行进程可能仍保留其启动时的环境；停用文件影响后续进程启动。

验证：7项开发板测试通过，覆盖账号匹配、精确保存密码、权限保护、符号链接拒绝、只向当前QQ注入凭据、环境污染清理及无效输入拒绝。账号读取、runuser合成环境传递、USB端到端保存测试通过。真实凭据的两次实测与最终成功结果见 密码自动登录实测说明（历史记录保留于本机归档，不随公开源码上传），密码从未输出到聊天或交付文件。

实现依据：[NapCat v4.18.42密码回退实现](https://github.com/NapNeko/NapCatQQ/blob/v4.18.42/packages/napcat-shell/base.ts)。
