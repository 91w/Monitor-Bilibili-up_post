# WebUI 访问与定时清理

运行 [打开正在运行的QQ管理页.cmd](../打开正在运行的QQ管理页.cmd)。工具检查 USB、恢复固定端口并打开带管理认证的页面。

固定入口：`http://127.0.0.1:16099/webui/`。它位于电脑上，通过 USB 转发到开发板 WebUI。关闭旧的13159端口标签页，使用新打开的页面。首次或管理认证失效时优先从工具进入。

如果显示Web Login的Token输入框，这是管理页认证，不是QQ账号退出。工具已改为直接打开官方认证路由并携带Token；仍需手动输入时点击工具里的“复制管理Token”，粘贴后登录。Token不显示在聊天或交付文件里，复制后60秒或关闭工具时清理仍属于本工具的剪贴板值。

- 关闭工具窗口后，转发继续保留，网页仍可访问。
- USB拔插、电脑或ADB服务重启后，重新连接并运行工具恢复入口。
- 该电脑回环入口依赖USB；开发板后台QQ和消息转发可以独立供电运行，不依赖网页一直打开。
- 网页打不开不等于QQ退出。重新打开WebUI本身不要求退出QQ；只有QQ要求手机验证时才需扫码。

本次检查发现电脑转发列表为空；开发板WebUI和QQ正常。恢复固定端口后，首页、6个入口资源及报错中的 `index-Mx73Ba53.js` 均返回HTTP200。处理过程中没有退出或重启QQ。

## 已启用的定时清理

维护进程由开发板init开机拉起，每60秒检查空间，每约10分钟统计用户数据。北京时间凌晨03:00后执行当天清理；若当时未运行或时间不可信，会在之后条件满足时补做，不需要电脑定时任务。

| 内容 | 保留规则 |
| --- | --- |
| 运行日志、诊断日志、崩溃转储 | 通常7天，另设分类容量预算 |
| 明确命名的浏览器缓存 | 通常30天，预算256 MiB |
| 三个旧安装包 | 14天 |
| apt下载缓存 | 通常7天 |
| 成功转发的图片副本 | 成功约1天后，转发进程每小时检查清理 |
| 成功消息正文与发送计划 | 成功约7天后清理，去重信息约90天后清理 |

打开中的文件、新生成文件及白名单外文件保留。失败消息及所需专用图片副本保留重试。详见 [存储维护策略](存储维护策略.md)。

## 原生消息库已启用容量触发维护

内部接口插件检查被官方白名单拒绝，没有修改白名单。后续改用停止QQ写入、备份轮换消息文件、由QQ重建的方式，已在实机验证并恢复在线。

每天03:00后检查白名单消息文件，达到3 GiB且两次至少间隔7天才轮换；清理前必须队列无积压、补查完成。旧备份验证通过满24小时后删除。低于阈值不会每天重启。清理可能触发手机授权，飞书会发送维护提醒。

这不是整个 `nt_db` 目录删除，也不是按7天逐条删除。登录、联系人、群资料、配置及转发队列保留；QQ退出期间存在接收空窗，补查能力取决于QQ可提供的历史。具体范围与恢复方式见 [原生消息库定时清理](原生消息库定时清理.md)。

只读占用核对：账号数据库目录约15 MiB，表情资源约170 MiB；表情资源未纳入删除范围。整个QQ用户目录不等于聊天数据库。
