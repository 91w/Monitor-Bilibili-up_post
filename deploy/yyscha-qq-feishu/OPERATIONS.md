## 电脑日常恢复

使用交付目录 `15-登录并加密同步开发板.cmd`，只在电脑回环地址打开恢复网页。完成验证码登录或 Cookie 导入后，在页面下方点击“验证并加密上传”，然后点击“查询／重试同步”。

- 已加密保存在本机：网络失败时保留同一个包和版本，后续查询/重试会继续上传。
- 密文已上传：COS 接收成功，仍需等待开发板处理。
- 开发板已确认验证并应用：电脑已核验板端签名回执。
- 拒绝：旧会话与消息队列保留，应重新验证后生成新包。
- 有效期已过而没有回执：不能推断板端完全没有应用；先复核板端状态，再重新验证上传。

正常健康时领取约 15 分钟一次，登录失效后约 60 秒一次，断网会退避。电脑无需长期运行；它关闭后无法自动重试尚未上传的本地包，但板端可以独立领取已经上传的包。现有 11 入口只更新本机，不替代新的 15 入口；旧 06 不应与板端正式发送同时使用。

`16-查询或重试开发板同步.cmd` 可读取最新出站状态、重试上传并认证回执，不会生成新版本；它查询的是会话更新结果，不是实时消息队列状态。

## 板端维护

程序位于 `/overlay/yyscha/app`，私密状态位于 `/overlay/yyscha/data`。仅对本项目操作：

```sh
sh /overlay/yyscha/app/yyschactl status
sh /overlay/yyscha/app/yyschactl logs
sh /overlay/yyscha/app/yyschactl updates
sh /overlay/yyscha/app/yyschactl session
# 经确认正式启用；发送已有 pending/retry 队列
sh /overlay/yyscha/app/yyschactl start
# 停止发送和自动领取，保留配置、会话、基线与队列
sh /overlay/yyscha/app/yyschactl stop
```

本项目的采集/发送与加密更新使用两个独立 inittab 守护项，已经安装并在 PID 1 下运行，保留原 B 站服务条目。适配了板端没有 nohup 的环境，手动控制通过 Python 脱离维护会话启动子进程。整机重启会短暂影响同板其他服务，尚未进行完整断电/重启验收。

当前仍由电脑 USB 供电，用户计划后续改为独立电源。软件已在板端运行，但电脑断电若导致 USB 断电，板端会停机；应先落实独立供电再验收“电脑关机后持续运行”。

交付目录的 07 和 17 入口通过 USB 查看板端队列，12 和 18 入口查看板端 Cookie 有效期元数据，不再展示电脑迁移前的旧数据。它们需要 USB/ADB；外网的 15 登录同步与 16 回执查询入口使用 COS，不需要 USB。

## 故障与回退

网络失败：保留出站密文、板端状态和消息队列，稍后重试。坏包、过期、旧版本、错误身份不应用；已应用包的重复领取返回原回执。网站读取不通过时不会替换旧会话。失效登录并不意味着网站会接受本地旧 Cookie 备份，必要时仍需正常重新登录。

程序版本回退前先停止本项目服务；保留实际最新的消息数据库，不要用上线前快照覆盖上线后发送结果，否则可能产生重复通知。使用 SQLite backup API 获取一致性快照，不拷贝活跃 WAL 文件做迁移。不得删除消息数据库来解决登录或同步故障。

配对文件与中转数据库同样重要：电脑发送身份、对端固定公钥和 `relay-upload.sqlite3`；板端身份、对端固定公钥和 `relay-receiver.sqlite3`。普通升级不覆盖这些文件。工具拒绝悄悄替换已有对端身份；重新配对必须通过可信通道显式撤销旧身份，并协调版本状态和云路径，不能只删某一端密钥后重建。自动轮换工具及完整轮换演练尚未交付，不从 COS 找回解密私钥。

两组云身份可独立撤销；撤销云凭据不等同于轮换本地解密或签名私钥。开发板云凭据已保存在板端私密目录，电脑 bootstrap 暂存已在比对板端副本后清理；用户自行保存的原始凭据备份不由程序遍历或删除，不将任何密钥打包到 outputs。
